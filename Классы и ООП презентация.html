const

const: чтение и изменение

const-метод можно вызвать у const-объекта.

Наблюдатель и операция
// Методы внутри Money
long long kopecks() const {
    return kopecks_;
}

void add(Money amount) {
    kopecks_ += amount.kopecks_;
}

const Money price(19990);
price.kopecks();     // OK
// price.add(Money(100)); // ошибка

Money total(19990);
total.add(Money(100));   // OK

kopecks() const

Читает количество копеек. В нашем Money такой метод не изменяет поле.

add(amount)

Меняет сумму у объекта, для которого вызван. Поэтому const у метода нет.

Account

Account использует Money

Счёт хранит денежную сумму и задаёт допустимые операции.

account.hpp · фрагмент
class Account {
public:
    explicit Account(Money initial)
        : balance_(initial) {
        if (initial.kopecks() < 0)
            throw std::invalid_argument(
                "отрицательный баланс");
    }
    bool withdraw(Money amount);
    void deposit(Money amount);
    Money balance() const {
        return balance_;
    }
private:
    Money balance_; // _ — соглашение в имени поля
};

Композиция

Объект Account содержит объект Money. У них разные обязанности.

Публичный интерфейс

Создать счёт, пополнить, снять, узнать баланс. Прямой записи в balance_ снаружи нет.

Снятие: неверная сумма → исключение;
денег не хватает → false;
успех → true.

Разбор решения

Разбор withdraw

Состояние меняется только после проверок.

solutions/sol0_account.cpp
bool withdraw(Money amount) {
    if (amount.kopecks() <= 0)
        throw std::invalid_argument(
            "сумма должна быть > 0");

    if (balance_.kopecks()
            < amount.kopecks())
        return false;

    balance_.subtract(amount);
    return true;
}

500 → снять 700

Результат false. Баланс остаётся 500.

500 → снять 200

Результат true. Баланс становится 300.

500 → снять −100

Исключение. Баланс остаётся 500.

Перегрузка операторов

Оператор += в Money

Новая запись уже знакомого изменения суммы.

Методы внутри Money
// Обычный метод Money уже знаком.
void add(Money amount) {
    kopecks_ += amount.kopecks_;
}

Money& operator+=(Money amount) {
    add(amount);
    return *this;
}

Money total(500);
total += Money(200);
// Теперь total хранит 700 копеек.

Что изменяется

Левый операнд: total. Проверенная логика остаётся в add().

Что возвращается

Money& — ссылка на изменённый объект. *this обозначает текущий объект.

Сложение Money

Оператор + возвращает новое значение

a + b сохраняет исходные a и b.

money.hpp · operator+
// Свободная функция, вне Money.
inline Money operator+(Money a, Money b) {
    a += b;
    return a;
}

Money price(500);
Money delivery(200);
Money total = price + delivery;

// price: 500; delivery: 200; total: 700

Почему исходные суммы сохраняются

Параметры a и b переданы по значению. Внутри функции изменяется копия a.

Одинаковое правило сложения

operator+ использует operator+=, а тот — add(). Логика сложения не дублируется.

Деструктор

Деструктор ScopeTrace

Специальная функция вызывается при уничтожении объекта.

Учебный вывод времени жизни
class ScopeTrace {
public:
    explicit ScopeTrace(
        const std::string& name)
        : name_(name) {
        std::cout << "ENTER " << name_ << '\n';
    }
    ~ScopeTrace() {
        std::cout << "LEAVE " << name_ << '\n';
    }
private:
    std::string name_;
};

Запись

~ScopeTrace(): имя класса с ~, без параметров и возвращаемого типа.

В наших примерах

Выход из блока, ранний return и раскрутка стека к обработчику исключения вызывают деструкторы локальных объектов.

Вызывать деструктор вручную для обычного локального объекта не нужно.

RAII

Зачем нужен RAII

Освобождение ресурса связываем со временем жизни владельца.

Проблема ручного закрытия
std::FILE* f = std::fopen("demo.log", "a");
if (!f)
    throw std::runtime_error("open failed");

if (cancelled)
    return; // Кто закроет файл?

perform_work(); // Может бросить исключение.

std::fclose(f);

Ресурс

Открытый файл требует закрытия. Одного fclose в конце функции недостаточно для всех путей выхода.

Владелец

Объект захватывает ресурс при создании и освобождает его при уничтожении.

RAII — Resource Acquisition Is Initialization.
В нашем примере ресурс принадлежит объекту FileLogger.

FileLogger

FileLogger владеет файлом

Минимальная обёртка: открытие в конструкторе, закрытие в деструкторе.

demo/file_logger.hpp · фрагмент
// Фрагмент public-части FileLogger
explicit FileLogger(const std::string& path)
    : f_(std::fopen(path.c_str(), "a")) {
    if (!f_)
        throw std::runtime_error(
            "не удалось открыть файл");
}

~FileLogger() {
    std::fclose(f_);
}

// private:
// std::FILE* f_;
Использование
{
    FileLogger log("demo.log");
    log.write("начали работу");
} // Деструктор закрывает файл.

Если открыть не удалось

Конструктор бросает исключение. Успешно созданного FileLogger не появится.

Полный класс запрещает копирование. Причину разберём следующим шагом.

Владение ресурсом

Почему FileLogger нельзя копировать

Два владельца одного FILE* попытались бы закрыть один файл дважды.

Запрет копирования
// В public-части FileLogger:
FileLogger(const FileLogger&) = delete;
FileLogger& operator=(const FileLogger&)
    = delete;

FileLogger first("demo.log");
// FileLogger second = first; // ошибка

Копия указателя

Копирование FILE* не открывает второй файл. Оба указателя обозначали бы один ресурс.

= delete

Запрещает соответствующую операцию при компиляции. В этой версии логгер остаётся в месте создания.

Готовые классы

Готовые классы тоже используют RAII

В обычном коде файл может принадлежать std::ofstream.

Стандартная библиотека · <fstream>
{
    std::ofstream out("demo.log",
                      std::ios::app);
    if (!out)
        throw std::runtime_error(
            "не удалось открыть файл");

    out << "готовый владелец файла\n";
} // std::ofstream закрывает файл.

Что делает готовый тип

Управляет временем жизни файла. Пользовательский деструктор для этого блока писать не требуется.

Зачем писали FileLogger

Чтобы увидеть, где ресурс захватывается, кому принадлежит и где освобождается.
